# 当前产品设计基线

本文只记录当前产品和交互中稳定、会影响实现选择的约定。具体字段、页面行为和接口契约以目标模块代码、
测试与 PostgreSQL 事实为准。

## 产品范围

Admin 是面向管理员的平台控制台。当前可见业务域：

| 域 | 当前入口 |
| --- | --- |
| 认证与账户 | 登录、个人中心、用户、会话、登录日志 |
| 权限管理 | 认证平台、菜单、角色、角色授权、Access 快照 |
| 系统运维 | 操作日志、健康/就绪检查 |
| 对象存储 | COS 配置、上传规则、凭证 |
| 消息 | 邮件与短信配置、站内通知、通知任务、模板、发送测试、发送日志、收件规则、限流策略 |
| 应用壳 | Dashboard、动态菜单、路由标签、语言切换、主题 |

新业务不因历史文档里出现过名称就视为已实现；先看 `server/internal/module`、`web/src/views` 和
`STATUS.md`。

代码中的复合业务模块名使用 lower camel case；页面模块、API 模块、后端模块、菜单 componentPath、权限码
和 i18n key 使用同一模块段。数据库表继续使用 snake_case，HTTP API 使用小写资源路径，Vue 组件使用
PascalCase，CSS class 与测试定位符使用 kebab-case。

## 体验基线

- 前端是 Vue 3 + TypeScript + Pinia + Vue Router + Element Plus；页面优先保持成熟旧项目的信息结构、工作密度
  和操作习惯，再接入当前 DTO、主题和公共组件。
- 页面负责编排状态、收集输入和展示 loading/empty/error/success；HTTP 调用只放在
  `web/src/api/<module>.ts`，经过 `web/src/utils/request.ts`。
- 优先使用已有 `AppDialog`、`AppTable`、`Search`、`DIcon`、`IconSelect`。只有多个真实页面已经复用且交互
  稳定时才新增公共组件。
- `AppDialog` 按内容自适应高度，整个弹窗最高 `90vh`；超出时仅正文内部滚动，标题与底部操作保留可见。
  业务弹窗不再指定 `height` 或嵌套固定高度滚动区。`center` 默认开启，表示视窗水平/垂直居中，不改变标题或
  按钮对齐；特殊场景可用 `:center="false"` 配合 `top`。
- 所有下拉选择使用 `el-select-v2` 的 `options` 数据契约，不使用 `el-select`/`el-option` 子节点；选项文案走
  所属后端模块按请求语言输出的 label（界面按钮/提示仍走前端 i18n），值保持 DTO 原类型；多选、可创建和
  禁用状态不得在迁移中降级。
- 所有可见文案走 i18n；JSON 和 TypeScript 字段使用 lower camel case。表格、树和分页保持可扫描的管理后台
  密度，并在窄屏下不产生遮挡或横向溢出。
- 跨模块语义稳定的基础按钮、通用表头和筛选文案统一使用 `common.*`，不保留模块级重复 key 或旧别名。
  公共组件使用相同默认文案时，页面不重复传入 label；业务专属按钮、校验、错误和具有不同影响范围的确认提示仍归所属模块。
- 系统设置按“高级设置 / 协议与隐私”分区，默认高级设置。媒体是值类型 `5`，与字符串、数字、布尔值和 JSON
  并列；在通用新增/编辑弹窗使用 UpMedia，上传编码为 `setting`，配置值仍为字符串对象键。默认头像、Excel 模板
  和自定义媒体设置均在高级列表维护，不设独立媒体页签；上传后保存才绑定，清除不删除 COS 文件。用户协议与
  隐私政策各维护一份富文本正文，不随界面语言拆分；保存即发布。登录页只提供查看入口，不以勾选协议作为登录
  前置条件；未配置或加载失败时明确展示状态。
- API 失败由请求层统一通知一次。自动刷新期间的中间 401 不通知；登录接口的凭据错误由登录页以内联状态展示，
  请求层不重复通知。页面只负责失败后的状态恢复、重试和业务动作，不重复弹同一错误。

删除和业务状态变更（启用/停用、通知已读、任务提交/取消/重试等）在发送请求前必须二次确认，取消或关闭确认不得发送请求或乐观修改列表状态。表单编辑已有记录的状态同样遵循此规则；新增记录的初始状态不视为状态切换，启用上传规则替换等既有确认保留。确认提示使用双语文案，明确操作对象及目标状态。操作按钮显式指定语义类型：查看/编辑 primary，停用 warning，启用 success，删除 danger。

管理表格的操作列使用纯文字按钮，不添加装饰图标；刷新、新增等工具栏按钮保留既有图标。启用类状态列统一为“状态”，列名使用 `common.status`；界面启用/停用文案只使用 `common.enable` / `common.disable`，不按英文是否带 `d` 拆分 key。后端提供的状态展示与候选 label 仍由所属业务模块拥有；同步、任务等不同业务状态保持各自语义。

配置缓存状态是同步监控视图。COS 作用范围显示实际配置名称和 ID；软删除或配置不存在的记录明确标记，保留同步历史与待同步数量，不将它们伪装成当前有效配置。

## HTTP 契约

成功和失败都使用精确 envelope：

```json
{
  "code": 0,
  "data": {},
  "message": "ok"
}
```

不接受 `msg` 或静默兼容字段。请求层校验 envelope、统一错误、鉴权和刷新；业务 API 仅声明 DTO 和调用泛型
HTTP 方法，不重复解析每个 DTO。后端负责类型、必填字段、数值、null/空数组、分页及公开错误语义的契约测试。
前端 strict 类型检查保留，泛型不被当作运行时校验。浏览器字节转换、实时帧和认证凭据等运输边界仍显式校验。

## 权限设计

页面、读取和动作是三种不同能力。新页面在设计阶段先列清映射：

| 节点 | 进入页面 | 列表/详情 | 写操作 | 隐藏 |
| --- | --- | --- | --- | --- |
| TARGET | `TARGET:view` | `TARGET:list` / `TARGET:detail` | `TARGET:create` / `TARGET:update` / `TARGET:status` / `TARGET:delete` / `TARGET:authorize` | `0` 或 `1` |

规则：

- 页面 `:view` 只控制能否进入；不得自动推导读取或写入权限。
- `is_hidden=1` 只是不出现在侧边菜单，仍需动态路由、页面权限和后端 Middleware。
- Access 的 `menuTree` 只放 directory/page，action 只放入 `permissionCodes`。
- 个人中心是隐藏页面：`user:profile:view`、`user:profile:detail`、
  `user:profile:update`、`user:password:update` 分别对应进入、读取、保存和改密。
- Page 和 action 完全独立；获得上传等 action 不会自动获得所属管理页面或目录。个人中心是隐藏根页面，
  不因个人能力暴露“用户与账号”目录。
- 前端按钮隐藏不是安全边界；后端 API 必须使用同一个 action code 再校验。

Canvas 的全局通用能力统一挂在 Canvas 平台的隐藏根 page `canvas:workspace:view` 下，当前包含
`storage:object:upload`，不为上传单独增加页面。普通角色只显式授予 upload action，不隐式授予工作区 page；
action 不进入 `menuTree`，也不因此产生侧栏或动态路由。个人资料仍保持独立的 `user:profile:*` 契约。
Canvas 上传规则由 Admin 管理，使用 Canvas 的 `platform_id` 和 `canvas` 编码；COS 逻辑配置可共享，
权限事实、规则选择及对象所属平台不能复用 Admin 身份或回退到其他平台。

## 数据和状态

- 腾讯云 SES 配置、邮件模板和收件规则全系统共享，不随 Admin/Canvas 等认证平台复制；只有发送日志、验证码
  记录和额度 key 保留来源平台。COS 逻辑配置同样全局共享且允许维护多条，上传规则按认证平台隔离，并通过
  `cosConfigId` 选择配置。
- COS 配置的物理 version 只用于定位对象写入时所在的 Bucket/Region/Endpoint，不承担管理员编辑冲突控制；
  配置 generation 只用于 Redis state/snapshot/lease/outbox 一致性。普通管理 CRUD 采用 last-write-wins，DTO
  不暴露 generation、revision 或 expected version。
- 邮件只保留每分钟、每 10 分钟两条发送上限；同平台、同邮箱跨所有场景和管理测试共享，任一达到上限
  即拒绝，不再叠加场景/IP/管理员专属策略。配置的次数、窗口与验证码 TTL 都由邮件管理拥有。
- 找回密码成功不自动登录，并撤销全部既有会话；首次设置密码只允许无密码账号，保持会话且不强制拦路。
- Admin 允许邮箱验证码自注册。未知邮箱验证码验证成功后原子创建无密码账号并绑定唯一默认
  `registered_user`；不开放绕过邮箱验证的密码直注册入口。默认角色只有个人中心/设密与上传 action，
  额外管理权限由管理员显式分配其他角色。
- Email 和 Phone 是同级用户身份：用户可以只有其中一个或同时拥有两个。`user/account` 与普通
  `user/profile` 只读展示身份，绑定/换绑分别由 `user/email` 与 `user/phone` 负责；首次绑定只需新身份 proof，
  换绑必须当前身份与新身份两份 proof，并以一次 `ConsumeMany` 原子消费。身份更新和 append-only 变更审计在同一
  PostgreSQL 事务中完成，唯一冲突、陈旧 current 与并发失败返回冲突语义，并使 authority generation 失效。
- Mail 与 SMS 是发送渠道，不是身份模块。Mail 使用 `login`/`forget`/`bind_email`/`change_password`，SMS 只使用
  `login`/`forget`/`bind_phone`/`change_password` 四个固定场景；两种渠道的模板、Provider、Redis namespace 和
  加密/HMAC key 独立。验证码改密按 `loginType=email|phone` 选择渠道，保留当前 Session 并撤销其他 Session；找回密码
  撤销全部 Session。

- PostgreSQL 保存用户、权限、菜单、配置、日志等业务事实；Redis 只做会话、Access 版本/快照和队列存储等
  明确用途，不成为第二个权限来源。
- 配置缓存固定覆盖 `system.setting/global`、`message.mail/global`、
  `message.sms/global` 和 `storage.cosconfig/<configId>`。权限的 menu/policy/access version、Session/authority
  generation、验证码、限流计数和队列数据保持各自业务语义，不迁入配置 generation。
- 字典管理及其通用数据库/缓存目录退出。业务枚举、候选项、默认值、限制、状态转换和可操作结论放回所属
  后端模块，静态 options 使用代码常量、按请求语言输出 `{value,label}`，不查 PostgreSQL/Redis；前端不维护
  第二份业务数值名单或按状态推断操作。性别保持 JSON 数字，地域/扩展名/MIME 保持字符串；上传可创建值仍由
  后端验证，不因删除字典丢失多选、自定义值和权限。未来真正可维护的数据建立具名业务资源，不恢复通用字典。
- 前端交叉检查后端 actions 与 Access action，写入时后端重新检查当前事实与并发状态。表单 rules 消费后端
  限制提供即时反馈，不能作为安全边界。语言切换拒绝过期 options；加载失败清空并明确展示，禁止猜默认值。
- 自有样式统一 SCSS，优先 Element Plus 和现有 AppDialog/AppTable/AppSearch；按独立交互职责或真实复用
  抽组件，不以 500/400 行上限碎片化拆分；第三方 CSS 保持原样。
- Yes/No 统一为 `0 = No`、`1 = Yes`。有真实删除行为时使用 `deleted_at`，不并列维护另一套删除标记。
- 页面状态必须区分初始加载、成功空态、失败、提交中和提交失败；不以空数组、默认对象或旧快照掩盖依赖错误。
- Mail 发送日志与验证码记录是审计事实，采用 append-only 语义，不提供管理员单条、批量删除或恢复操作。
  认证平台软删只停止服务，不抹除历史来源；审计列表必须继续显示原平台 code。

## 实时通知

- 一个通知任务固定一个认证平台，受众为指定用户、提交时点冻结的指定角色或平台全体；平台广播不展开百万用户，发布后新建账号不可见，长期离线用户仍可在保留期内从 PostgreSQL 邮箱读取。
- 草稿采用 last-write-wins，只允许草稿编辑和删除；提交后标题、富文本、展示类型、优先级、链接、平台、受众和发送时间全部冻结。取消只停止后续批次，不撤回已经生成的通知；已提交任务通过复制产生新草稿。
- 正文使用模块内简化富文本编辑器，只开放粗体、斜体、下划线、H2/H3、列表、HTTPS 链接、撤销/重做和清除格式；不提供图片、视频、文件、表格、代码、字体、颜色或源码模式。内部链接必须是应用路由，外部链接只接受 HTTPS。
- 顶栏铃铛只在 Access 已就绪且具有 `message:notification:list` 时工作，展示未读数和最近 5 条；`message:notification:view` 独立控制进入隐藏通知中心，read/delete action 各自控制已读和删除。普通通知只刷新邮箱，紧急通知只由多标签 leader 弹一次。
- 通知中心提供 all/unread、展示类型和优先级筛选，使用 ID cursor 加载更多；没有撤回、归档或恢复。通知和 realtime event 保留天数由系统设置管理，缩短保留期必须二次确认，已清理数据不会因调大配置恢复。

## 旧项目迁移

迁移已有功能时只读取对应旧项目的直接页面/接口和调用方：成熟行为、字段语义、筛选分页、危险操作确认和
信息结构优先继承；重型分层、兼容协议、重复状态和无真实用途抽象按当前架构替换。未得到用户或当前任务
确认，不删减已存在的成熟功能。

项目尚未上线期间，经维护者确认的破坏性重构直接切换到新表、新 DTO、新权限和新 Redis 协议；正常运行时不保留
旧字段、旧 key、旧对象格式的双读、双写或回退分支。需要清理的旧 Redis key 只由固定 pattern 的一次性 migration
命令处理。

## 我的文件

云服务下“我的文件”只管理登录用户在当前认证平台上传的文件；管理员和超级管理员同样只能查看本人文件。支持真实分页、按上传时间倒序、文件名搜索和类型筛选，以及上传、预览、下载、删除。删除必须二次确认；删除请求受理后文件退出本人列表，后台完成 COS 清理，失败保留可重试意图。

文件库页面与头像选择弹窗复用同一分页浏览组件。选取头像时只记录本地选择，保存资料时后端校验本人归属和图片条件，服务端复制为独立对象并保存副本 Key。删除文件库原图不影响头像，更换头像不影响原图；未改头像保持原值，清空头像由所属业务清理已登记副本。历史对象不猜测上传者，不强制回填。

文件浏览使用卡片网格；顶部保留搜索、上传和刷新，底部保留后端真实分页。图片/视频展示缩略区域，其他文件显示类型图标，卡片展示文件名、类型、大小和上传时间；预览、下载、删除使用纯文字按钮，桌面悬停或键盘聚焦显示，触屏常显。图片预览使用全屏 `el-image-viewer`，提供缩放、适应、旋转和下载；视频/音频使用媒体控件，普通文件不提供预览入口，只保留下载和删除。选择弹窗复用卡片，支持点击或键盘选择，预览/下载不会触发选择。

上传采用签名直传暂存对象，后端核对 COS 对象后提升到最终对象并完成登记；前端不能以 PUT 成功替代业务上传完成。文件库上传由后端匹配 `file` 编码，头像选择弹窗上传匹配 `avatar` 编码；编码和 COS 配置不是用户选择项，不展示上传规则下拉，也不回退到其他用途。后端返回当前场景唯一可用规则的格式和大小限制，前端只展示上传入口和大小提示；没有可用规则时明确提示，不猜默认配置。文件名、类型搜索提供随语言切换的 placeholder，搜索、文件浏览、上传和弹窗复用现有公共组件。列表不展示内部生命周期、COS 物理版本或启用/停用。原件、独立头像副本与可恢复清理事实使用同一张文件表，不增加文件引用表。

核心上传组件 `UpMedia` 的 `variant` 固定为 `image`、`video`、`file`、`button`。图片和视频使用正方形：空值为加号上传入口，已有值显示缩略图，悬停或键盘聚焦显示预览、删除图标；触摸设备常显操作。图片复用 Element Plus Image Viewer，提供缩放、旋转和下载；视频按需打开播放器，不自动播放。单值更换可先清除再上传，多值保留加号入口。文件使用上传按钮和附件行，附件行保留文件图标、文件名、下载、清除；按钮模式只提供上传入口并通过 `uploaded` 交给页面刷新，不绑定多余的页面状态或请求签名预览。

`allowFileLibrary` 默认关闭，只控制“选择我的文件”入口；图片/视频入口在正方形下方，文件/按钮入口与上传按钮并排。上传权限与文件库选择权限独立，由调用方传入。公共组件不出现头像专属文案；删除/清除立即移除本地待保存选择，不弹确认、不调用保存或文件删除接口，不影响“我的文件”原件。保存由所属业务提交，文件库中真正删除文件仍需二次确认。系统设置值类型固定为 5=媒体-文件（按钮和附件行）、6=媒体-图片/视频（正方形）；默认头像使用 6 且仅允许图片，Excel 模板使用 5。后端选项与 DTO 返回对应形态和格式限制，前端不推断设置键；公共上传组件仅按媒体格式选择图片或视频预览元素，上传规则、归属和完成校验仍由后端负责。

## 支付余额约定（维护者已确认，支付业务尚在建设）

同一用户账户的余额允许为负数。余额与流水历史前后余额使用有符号整数和精确金额字符串，不归零、不隐藏负号；充值套餐、支付订单和兑换码面额仍必须为正数，充值按原余额加实际入账金额执行。不得把余额当作累计充值统计，或重复增加欠款余额、授信额度、透支开关字段。允许负余额不自动决定负余额用户的消费准入或无限透支规则，AI阶段按实际需求另行确认。

支付配置先沿用旧项目支付宝证书模式：三份证书支持本地 CRT/PEM 文件导入或粘贴；创建时填写私钥，发布新版本时空白凭据表示保留，普通编辑仅改名称/排序。provider/environment/appId/sellerId 创建后固定，同一通道的凭据版本不可编辑或删除。provider=1支付宝/2微信保留、environment=1沙箱/2生产、payMethod=1PC网页/2H5；首期只有支付宝可配置。回调输入 HTTPS 模板 `/api/admin/v1/payment/callback/alipay/{configId}/{version}`，服务端按创建后的坐标保存完整 URL；实际回调入口及支付保护边界见下文。本地配置校验不是实时支付或通道连通测试，不返回密钥、密文或原始证书。

支付配置使用数据库 ID 关联，不再要求管理员填写内部编码；provider/environment/appId/sellerId 创建后固定，同一通道的凭据版本不可编辑或删除。

证书 `NotBefore`/`NotAfter` 仅作为证书元信息展示，不参与新增、凭据换版、本地配置校验或启用操作的拦截。支付凭据校验只检查 PEM/DER 格式、RSA 强度、证书用途、APPID/PID 身份、私钥与应用证书匹配，并要求 SDK 成功初始化及使用配置证书验签；不改写入库证书内容。本地校验通过不代表下单、到账或公网回调已联通。

支付回调已接入独立 Provider 路由 `/api/admin/v1/payment/callback/alipay/:configId/:version`，不经过用户鉴权；服务端只保留闭合验签事实并在同一事务内编排订单入账。P3 恢复与巡检完成前，生产环境购买保持关闭。

支付环境以后台支付配置的 `environment` 为唯一来源，下单选择已启用的可用配置，已有订单回调/查单始终绑定原 `configId/configVersion`；API/Worker 不读取 `PAYMENT_ENVIRONMENT`。完整 HTTPS `notifyUrl` 继续在支付配置页面维护，与前端地址和 CORS 无关。充值页面在提交时自动取当前页面 URL（保留路径/query、去掉 fragment）作为 `returnUrl`，后端校验绝对 HTTP(S) URL 格式后作为支付宝下单参数传递，不再提供手填回跳地址或读取 `PAYMENT_RETURN_ORIGINS`；到账仍只能来自验签回调或可信查单，不根据浏览器回跳参数加款。生产购买保护门暂时保留，按订单关联配置的环境判断，不借本次配置收口开放生产支付。

订单巡检收到支付宝“交易不存在”时，必须先用订单绑定的凭据版本验证原始响应签名、证书序列号和订单号，并确认响应码为 `40004 / ACQ.TRADE_NOT_EXIST`。本地订单到期后才允许按现有租约条件关闭，未到期继续等待；网络错误、验签失败和其他网关错误不得作为关单依据。不生成支付或入账事实，迟到的真实支付凭据仍沿用已有幂等入账流程。

钱包使用“我的钱包 / 充值中心”两个 Tab，不展示大横幅；余额卡集中提供充值和兑换入口。充值套餐使用可选卡片展示名称、金额和徽章，并支持独立输入自定义金额（右侧数字控制器、最多两位小数）。最低自定义充值金额由系统内置设置 `payment.recharge.minimum_amount` 提供，单位元、初值 10，只允许 1..92233720368 的整数，不可停用或删除；套餐金额不受该最低值约束。支付不可用或选项读取失败时明确展示状态并阻止下单。

## 定时任务

主页面只展示计划表，提供计划下拉筛选；每行“执行记录”打开该计划的弹窗表格，按创建时间倒序、同一时间按 ID 倒序，使用后端分页与总数，不混合展示其他计划记录。执行状态保持后端提供的真实生命周期选项；切换状态、计划或每页条数回到第一页。详情和重试分别受独立动作权限控制，重试能力与后端 actions 交叉检查。程序式确认框的确定/取消按钮跟随应用语言。

执行记录弹窗最大宽度为 1400px，同时限制为视口宽度的 94%；创建时间列使用 240px，完整显示日期与时分秒。窄屏继续使用公共弹窗的自适应及表格内部横向滚动，不裁切时间内容或让弹窗超出视口。

执行记录的总数与分页栏常驻弹窗正文底部，滚动长列表时保持可见且不遮挡末行；复用现有 AppTable 响应式分页交互，不改变查询条件、分页参数或排序。

调度器保留计划、持久任务和执行尝试三张表。任务状态显示为待执行、排队中、执行中、执行成功、执行失败、已取消；执行尝试使用执行中、执行成功、执行失败。队列名称和超时由后端代码中的任务定义提供；每次尝试保留 Worker 归属、时间、耗时和错误分类，任务表不重复保存 Worker 快照。错误文案由后端根据分类及请求语言生成，不直接展示依赖服务的原始异常。

### 兑换码展示与存储

兑换码直接明文存储，管理员列表、详情、生成结果和导出均可查看完整码并复制，不设计一次性展示、脱敏或密钥解密交互。生成仍使用随机 20 位规范码；面额、状态和有效期保持后端事实，查询/兑换输入可归一化。明文展示仍受独立管理动作权限约束，个人用户只拥有钱包兑换动作，不获得管理列表权限。

兑换码批次备注展示于管理员列表、详情和 CSV 导出，空值显示“—”；备注只从关联批次读取，不重复存储到每条兑换码，也不通过个人兑换响应公开。CSV 保留引号、逗号和换行，并转义可能触发表格公式的前导内容。

### 维护资源启停状态

维护资源对外统一使用数值 status：0=停用、1=启用，前端消费后端选项与 actions；不再暴露 isEnabled 或自行派生另一套状态值。任务执行、订单等生命周期状态保留原有枚举。
